# Deployment Guide — Our Little Space on Render

This guide walks you through deploying the app to Render. No prior DevOps experience is required — just follow the steps in order.

## Overview

The app runs as a **single Render web service** that serves both:
- The Django backend API (Daphne ASGI server)
- The React frontend (built with Vite, served by WhiteNoise)

A **Render PostgreSQL database** is attached as a separate service and connected via environment variables.

A persistent Render disk is mounted at `/app/backend/media` so avatar uploads survive redeploys.

## Files Created for Deployment

| File | Purpose |
|------|---------|
| `Dockerfile` | Multi-stage Docker build: builds Vite frontend, then runs Django backend |
| `render.yaml` | Render blueprint (web service, PostgreSQL database, env vars, disk, health check) |
| `docker-compose.yml` | Local development parity (optional, for testing locally with Docker) |
| `start.sh` | Container entrypoint: runs migrations, collects static files, starts Daphne |
| `backend/.env.example` | Reference for all backend environment variables |
| `frontend/.env.example` | Reference for frontend environment variables |

## Step 1: Push Code to GitHub

1. Commit all changes (including `render.yaml`) and push to GitHub.
2. Make sure `railway.json` has been removed (it is no longer used).

## Step 2: Create the Render Blueprint

1. Log in to [https://render.com](https://render.com) (sign up with GitHub if needed).
2. Go to the **Blueprints** page and click **"Connect a repository"**.
3. Select the `our-little-space` repository.
4. Render will detect `render.yaml` and propose:
   - A **web service** (`our-little-space`) built from the Dockerfile
   - A **PostgreSQL database** (`our-little-space-db`)
   - A **persistent disk** (`media-disk`) mounted at `/app/backend/media`
5. Click **"Apply"**. Render will provision the database, create the web service, and start the build.

## Step 3: Set Required Environment Variables

Once the web service is created, go to the service → **Environment** tab and add/confirm these variables:

| Variable | Value | Purpose |
|----------|-------|---------|
| `SECRET_KEY` | Generate a random 50+ character string | Django's cryptographic signing key (auto-generated by render.yaml) |
| `DEBUG` | `False` | Disables debug mode for production |
| `USE_POSTGRESQL` | `True` | Use the Render PostgreSQL database |
| `ALLOWED_HOSTS` | `your-app.onrender.com,your-custom-domain.com` | Comma-separated list of allowed hostnames |
| `CORS_ALLOWED_ORIGINS` | `https://your-frontend-domain.com` | Origins allowed to call the API |
| `CSRF_TRUSTED_ORIGINS` | `https://your-frontend-domain.com` | Origins trusted for CSRF cookies |
| `SECURE_SSL_REDIRECT` | `True` | Redirects HTTP to HTTPS |
| `SESSION_COOKIE_SECURE` | `True` | Session cookies only over HTTPS |
| `CSRF_COOKIE_SECURE` | `True` | CSRF cookies only over HTTPS |
| `SECURE_HSTS_SECONDS` | `31536000` | HSTS header (1 year) |
| `SECURE_HSTS_INCLUDE_SUBDOMAINS` | `True` | Apply HSTS to subdomains |
| `SECURE_HSTS_PRELOAD` | `True` | HSTS preload |
| `SECURE_PROXY_SSL_HEADER` | `HTTP_X_FORWARDED_PROTO,https` | Trust Render's proxy for HTTPS detection |
| `LOG_LEVEL` | `INFO` | Application log level |

The `POSTGRES_*` variables (`POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_HOST`, `POSTGRES_PORT`, `POSTGRES_SSLMODE`) are linked automatically from the Render database via `render.yaml`; you do not need to set them manually.

## Step 4: Add a Custom Domain (Optional)

1. Go to your web service → **Settings** → **Custom Domains**.
2. Add your domain and follow the DNS instructions Render provides.
3. Add the domain to `ALLOWED_HOSTS`, `CORS_ALLOWED_ORIGINS`, and `CSRF_TRUSTED_ORIGINS` in the Environment tab.

## Step 5: Deploy

1. Render builds automatically: frontend builds with Vite, backend installs Python dependencies, static files are collected.
2. Once deployed, Render assigns a URL like `https://your-app.onrender.com`.
3. Render performs a health check on `https://your-app.onrender.com/api/health/` — it should return a JSON health response.

## Step 6: Verify Deployment

1. Open your Render app URL in a browser.
2. Visit `https://your-app.onrender.com/api/health/` — should return a JSON health response.
3. Visit `https://your-app.onrender.com/` — should show the React frontend.
4. Register a user, log in, and test core features.

## Step 7: Run Migrations After First Deploy

The `start.sh` script runs `python manage.py migrate --noinput` automatically on every container start (including deploys). No manual migration step is needed.

## Local Development with Docker

```powershell
# Build and run locally
docker-compose up --build

# The app will be available at http://localhost:8000
```

## What Still Needs to Be Done in the Render Dashboard

These steps **must** be performed in the Render web dashboard — they cannot be automated from the repository:

1. **Connect the repository** — Link your GitHub repository to Render Blueprints
2. **Apply the blueprint** — Create the web service + PostgreSQL + disk
3. **Set `SECRET_KEY`** — Render auto-generates it; confirm or replace it
4. **Set domain variables** — `ALLOWED_HOSTS`, `CORS_ALLOWED_ORIGINS`, `CSRF_TRUSTED_ORIGINS` with your actual domain
5. **Enable auto-deploys** (optional) — Render redeploys on every push to the connected branch
6. **Add custom domain** (optional) — Configure DNS through Render

## Health Check

The health check endpoint is at `/api/health/`. Render checks this endpoint to confirm the service is healthy. If it returns non-200, Render will restart the container.

## Rollback

In the Render dashboard, go to your web service → **"Deploys"** → select a previous deployment → **"Rollback to this deploy"**.

## Security Notes

- `DEBUG` must be `False` in production
- `SECRET_KEY` must be unique and never committed to version control
- All cookies are secure (HTTPS-only) when `SECURE_SSL_REDIRECT=True`
- HSTS is enforced for 1 year after HTTPS is verified
- Media uploads are stored on the persistent Render disk
- The frontend build output is baked into the Docker image at build time
- Never commit `.env` files or expose backend secrets through Vite variables
